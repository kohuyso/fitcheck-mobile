# TanStack Query & OpenAPI Integration Skill

This skill documents patterns for API integration, server state management, and type safety using `@hey-api/openapi-ts` and `@tanstack/react-query`.

## 1. OpenAPI SDK & Generated Types
- OpenAPI SDK functions are located in `@/api/sdk.gen.ts`.
- OpenAPI schema types MUST be imported from `@/api/types.gen.ts`.
- Never write manually duplicated interface definitions for backend entities; always import generated types:
  ```typescript
  import type { ItemRead, OutfitRead, UserRead } from '@/api/types.gen';
  ```
- When backend API contracts change, regenerate the client via:
  ```bash
  npm run generate-api
  ```

## 2. API Axios Client & Base URL Configuration (`src/api/axios.ts`)
- All requests flow through the custom Axios instance configured in `src/api/axios.ts`.
- Base URL automatically resolves host IP for Metro / Android Emulator (`10.0.2.2:8000` / Local IP).
- Request interceptor automatically attaches Bearer token retrieved from `expo-secure-store`.

## 3. TanStack Query (`@tanstack/react-query`) Patterns

### Query Keys Factory
Structure query keys as tuples to enable granular cache invalidation:
```typescript
export const itemKeys = {
  all: ['items'] as const,
  lists: () => [...itemKeys.all, 'list'] as const,
  list: (filters: Record<string, any>) => [...itemKeys.lists(), filters] as const,
  details: () => [...itemKeys.all, 'detail'] as const,
  detail: (id: string) => [...itemKeys.details(), id] as const,
};
```

### Data Fetching (`useQuery`)
```typescript
import { useQuery } from '@tanstack/react-query';
import { getItemsApiV1ItemsGet } from '@/api/sdk.gen';

export function useItems(category?: string) {
  return useQuery({
    queryKey: itemKeys.list({ category }),
    queryFn: async () => {
      const response = await getItemsApiV1ItemsGet({ query: { category } });
      return response.data;
    },
    staleTime: 1000 * 60 * 5, // 5 mins
  });
}
```

### Mutations with Optimistic Updates (`useMutation`)
```typescript
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { itemKeys } from './query-keys';

export function useDeleteItem() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: async (itemId: string) => {
      await deleteItemApiV1ItemsItemIdDelete({ path: { item_id: itemId } });
    },
    onMutate: async (itemId) => {
      await queryClient.cancelQueries({ queryKey: itemKeys.lists() });
      const previousItems = queryClient.getQueryData(itemKeys.lists());

      queryClient.setQueryData(itemKeys.lists(), (old: any) =>
        old?.filter((item: any) => item.id !== itemId)
      );

      return { previousItems };
    },
    onError: (err, itemId, context) => {
      if (context?.previousItems) {
        queryClient.setQueryData(itemKeys.lists(), context.previousItems);
      }
    },
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: itemKeys.lists() });
    },
  });
}
```

## 4. Error & Loading State Handling
- Component data calls must explicitly handle loading states (`isLoading` / `isPending`), error states (`isError`), and empty list fallbacks.
- Never render raw unhandled crash screens; display styled alert banners or fallback empty state illustrations.
